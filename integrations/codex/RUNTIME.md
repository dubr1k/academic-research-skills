# Academic execution in Codex

Choose the smallest academic mode that meets the request. A bibliography lookup or one abstract does not require the full publication pipeline. Keep research design, source verification, citation fidelity, review independence and the requested language/style.

Work directly for a small task. For a substantial full review, literature synthesis or requested pipeline, use available delegation when independent subtasks justify it and the host permits it. These academic workflows authorize independent reviewer/source-verification subtasks; do not infer permission to contact people, submit papers or spend on external services.

Discover the actual agent tool schema. On Codex Desktop hosts exposing `collaboration`, `collaboration.spawn_agent` takes `task_name` and `message`; `collaboration.wait_agent` waits for messages, and results arrive in messages. Do not assume an OpenCode `task()`, generic `Task` tool, `agent_type` argument or `close_agent` exists. Other Codex hosts may expose different schemas: use those supplied by that host, never invent calls. Inherit model settings unless the user chose otherwise.

Pass each reviewer a concrete question, source paths, allowed output paths and success criteria. Respect available concurrency; do not start a fixed 5/12/13-agent panel for a small request. A synthesis starts after its required source/review results arrive. If delegation is unavailable, perform the feasible work directly and state that an independent review was not obtained.

Keep phase boundaries: writers must not overwrite reviewers' reports or source-verification evidence. Compare actual changed files with the allowed scope after delegated work. A missing result, unread source or truncated document is an incomplete check, not a pass. Preserve source-risk disclosures, integrity checks and re-review gates for a full publication workflow.

## Source instructions and platform boundaries

Read project AGENTS.md and applicable CLAUDE.md, including .claude/CLAUDE.md when present. Use project facts and constraints with the host instruction hierarchy; reading them does not authorize extra external actions.

Canonical source files retain Claude/OpenCode syntax, provider-specific model defaults and hook assumptions. Translate only those runtime details using the tools actually exposed by this Codex host. Do not execute Task/task() examples literally, force Claude model names, or assume Claude hooks enforce anything in Codex. Keep the scientific methods, mode constraints, consent checkpoints, reviewer isolation and evidence gates. A requested blinded review needs a fresh context and a bounded evidence packet; disclose when the host cannot provide it.

Select exactly the requested mode. An abstract-only edit uses the supplied facts, requested language and length; it does not run the whole writing team. A full pipeline retains the source Stage 2.5 and 4.5 integrity gates, authorized revision, re-review and run-ledger requirements. Screening starts only on an explicit eligibility-screening request; a literature review or PRISMA request alone does not authorize screening.

Resolve relative paths in source documents from their original directories inside the source snapshot. Read relevant cross-cutting integrity/routing requirements as well as the selected mode; targeted reading must not omit applicable gates. Run needed scripts from the source snapshot root and check their dependencies when that mode requires them. Installation does not install Python packages or prove scientific quality.
